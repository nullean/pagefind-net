# AGENTS.md

pagefind-net is a pure .NET library that writes [Pagefind](https://pagefind.app/)-compatible search indexes, with no
native binaries and no subprocess. It targets Pagefind 1.5.2 (`PagefindIndex.PagefindTargetVersion`).

## Layout

| Path | What it is |
|------|------------|
| `src/Pagefind.Net` | The indexer: `PagefindIndex`, `PagefindRecord`, tokenizer, stemmer, writers. Packable, AOT-compatible. |
| `src/Pagefind.Net.Frontend` | Ships `pagefind.js` and `wasm.en.pagefind`; an MSBuild target copies them into `wwwroot/pagefind` on build. |
| `tests/Pagefind.Net.Tests` | TUnit tests, including parity against fixtures generated by the official Pagefind (`generate-fixtures.mjs`). |
| `tests/Pagefind.Net.E2E.Tests` | E2E tests that host `examples/Pagefind.Net.Web` on Kestrel and search it in the installed Chrome, headless, over CDP (Nullean.Cdp); rendered results are compared with `.snapshots/` (Nullean.Snapshots). |
| `examples/` | `Pagefind.Net.Example`, `Pagefind.Net.Web`, and `Pagefind.Net.Smoketest` (CI publishes it with Native AOT and runs it). |
| `build/scripts` | The F# build ([Nullean.Make.Fs](https://www.nuget.org/packages/Nullean.Make.Fs), net11.0); `./build.sh <target>` runs it. |
| `docs/`, `scripts/` | The docs-builder site and its post-build scripts. |

Package versions live in `Directory.Packages.props` and package metadata in `Directory.Build.props`. Each package
ships an agent skill, `src/<Project>/skills/<name>/SKILL.md`: when the public API changes, update its skill, and
compile any snippet you change.

## Build and test

`mise install` provides the toolchain: the .NET 11 SDK pinned in `global.json`, plus the net10.0 runtime the projects
and tests target. The everyday tasks have the same names as in every nullean repository:

```bash
mise run build            # build the solution
mise run test             # build, then run the unit and E2E tests
mise run pack             # build, pack the NuGet packages and validate them
mise run ci               # what CI's build job runs: test, curb check, then pack, validate and diff the public API
mise run docs             # build the docs and serve them
mise run format           # format the repository with curb
mise run check            # formatting drift (curb) and workflow security checks (zizmor)
mise run clean            # delete build output
mise run release          # show the release draft; `mise run release publish` releases
```

`./build.sh <target>` runs the same build targets directly (`./build.sh --help` lists them). The E2E tests need
the installed Chrome and nothing else: Nullean.Cdp finds it (`CDP_CHROME` names another), so there is no browser to
download. They snapshot the rendered results; a changed snapshot fails with its received file and the accept command,
and `SNAPSHOT_ACCEPT=1 mise run test` accepts locally after reading it (CI never accepts).

Build targets are Make.Fs `target { }` blocks in `build/scripts/Program.fs` whose commands are Proc.Fs `sh $"…"`
lines; values come from `text`/`lines` inside `shell { }`. Do not call the C# `ProcNet` API from the build.

## Releasing

release-drafter keeps a draft release up to date from the labels of merged pull requests; every pull request carries
exactly one release label (`pr-labels.yml` enforces it). **Publishing the draft** releases: it creates the tag and runs
`ci.yml` on it, whose `build` job tests, packs at the tag's version (MinVer), pushes to nuget.org with trusted
publishing and appends the public API changes to the release notes. Pushing a tag on its own does nothing. In 0.x a
`breaking` label bumps the minor version; 1.0 is the maintainer's call. See the
[releasing](.claude/skills/releasing/SKILL.md) and [breaking-changes](.claude/skills/breaking-changes/SKILL.md)
skills, and `mise run release` for the current draft.
